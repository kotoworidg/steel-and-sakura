# Architecture

The target is a manual Shogun 2 PFH3 Mod pack for the original Sengoku campaign. `scripts/prepare_infantry_source.py` clones verified rows from the user's installed game tables into four local JSON inputs. `src/infantry_localisation.json` contains authored English text using observed localization key patterns. `scripts/generate_infantry_icon.py` draws five original TGA cards at dimensions measured from installed cards. `scripts/rpfm_mcp.ps1` passes these files to RPFM v5.2.0's MCP server, saves a Mod pack, then reopens and extracts the packed files to verify them. `scripts/validate_offline.py` compares every generated DB row to its installed source row and checks schema, keys, localization, and icon headers. `scripts/build.ps1` runs these steps and regression tests in order.

The actual pack now contains **one provisional new unit**, Automatic Rifle Squad. The eventual three-unit goal is retained in `src/unit-specs.json`; tank and aircraft have no DB rows or disguised substitutes. Generated game-derived JSON, decoded tables, editor binaries, backups, and pack outputs are Git-ignored. The safe source ZIP includes scripts and intent/specification files; the local prototype ZIP includes the generated pack and explicit test limits.

The current infantry row joins four observed game tables: land stats, unit metadata, Fort recruitment, and `japan` military permission. Localization and icon files are packed, but their in-game lookup remains unverified. Variant and custom-battle integration also remain unverified, as listed in `LIMITATIONS.md`. Schema and packaging success must never be interpreted as runtime success.
